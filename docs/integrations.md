# Integrations

An integration in ObserveCraft is a Datadog Agent check (or an OpenTelemetry receiver) plus what comes with it:
dashboards, log pipelines and monitors. The checks run in the Datadog Agent, which sends their metrics, service
checks and logs to the ObserveCraft intake (see [Sending data](sending-data.md)). ObserveCraft has no agent of its
own, so any check the Agent can run works here.

The catalog (*Integrations → Integration Catalog* and *Integrations → Community*) is imported from Datadog's open
repositories, `DataDog/integrations-core` and `DataDog/integrations-extras` (BSD-3-Clause). When an integration's
metrics arrive, its dashboards are installed for the organization; its log pipeline is in
*Logs → Configuration → Pipelines → Library*.

## Install a community integration

Integrations under *Integrations → Community* come from `integrations-extras` and aren't shipped with the Agent.
Install them on the Agent by name and version (the integration's *Configure* tab shows its configuration):

```bash
sudo -u dd-agent datadog-agent integration install -t datadog-<integration>==<version>
```

In containers, build an Agent image with the integration installed (`agent integration install -r -t …` in a
Dockerfile `FROM` the Agent image) and use it in the Datadog Helm chart or Operator. Datadog's guide covers every
platform: [Use Community and Marketplace Integrations](https://docs.datadoghq.com/agent/guide/use-community-integrations/).

Then configure the check (`conf.d/<integration>.d/conf.yaml`, or Autodiscovery annotations in Kubernetes) and point
the Agent at ObserveCraft as for any other check.

## Build your own

- **A custom Agent check** — a Python class in the Agent's `checks.d`, the quickest way to collect something the
  catalog doesn't have: [Writing a Custom Agent Check](https://docs.datadoghq.com/extend/custom_checks/write_agent_check/).
- **A full Agent-based integration** — a package with tests, configuration spec, `metadata.csv`, dashboards and log
  pipelines, built with Datadog's `ddev` tool:
  [Create an Agent-based Integration](https://docs.datadoghq.com/extend/integrations/agent_integration/). Build the
  wheel (`ddev release build <integration>`) and install it on your Agents with
  `datadog-agent integration install -w <wheel>`; publishing it with Datadog is not needed to use it here.
- **Prometheus / OpenMetrics endpoints** — often no code at all: the Agent's `openmetrics` check, or an OpenTelemetry
  Collector with the Prometheus receiver.

## Bring its dashboards, log pipelines and monitors

ObserveCraft speaks Datadog's configuration API (see [Datadog API compatibility](datadog-api.md)), so an integration's
assets in Datadog's format load as they are, with an application key:

- **Dashboards** — `POST /api/v1/dashboard` with the dashboard JSON (`assets/dashboards/*.json`), or Terraform's
  `datadog_dashboard_json`.
- **Log pipelines** — *Logs → Configuration → Pipelines*, or `POST /api/v1/logs/config/pipelines` /
  `datadog_logs_custom_pipeline`.
- **Monitors** — `POST /api/v1/monitor` / `datadog_monitor` (`assets/monitors/*.json` holds the definitions).

## Add it to the catalog

The catalog is generated by `scripts/import-integration-catalog.mjs` and the importers next to it, from the pinned
revisions of `integrations-core` and `integrations-extras`. Datadog now publishes new integrations through its own
platform, so an integration that isn't in those revisions is added to ObserveCraft by a pull request: see
[CONTRIBUTING.md](../CONTRIBUTING.md).
